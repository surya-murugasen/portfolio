Architecture Deep Dive

TeamTrack – Real-Time Project Management Platform

Status: Source Available • Local Demo GitHub Repository

1. Problem Statement

Agile engineering teams require immediate visibility into task status transitions, document version revisions, and sprint workloads. Polling REST APIs creates high server load and introduces up to 10–30s latency, causing conflicting updates across remote developers.

2. Requirements & Constraints

  • Sub-200ms real-time event dissemination across connected clients.
  • Role-Based Access Control (RBAC): Admin, Project Manager, and Developer permissions.
  • Secure inter-service integration endpoint for external telemetry aggregators without exposing user credentials.

3. System Architecture

+------------------------+ HTTP REST (JWT Auth) +---------------------------------+ | Next.js / React Client | <============================> | Node.js / Express API Server | +------------------------+ | - Controller / Service Layer | | | - Role-Based Access Control | | WebSockets (Socket.IO) +---------------------------------+ | | +------------------------+ HMAC-SHA256 Signature Auth | Sequelize ORM | Central Admin / Health | <------------------------------> [hmacAuth.ts] | +------------------------+ v +---------------------------------+ | MySQL Relational Database | | - Users, Projects, Tasks, Logs | +---------------------------------+

4. Technology Choices & Rationale

Node.js + TypeScript: Single event loop provides high-concurrency I/O for Socket.IO while TypeScript eliminates runtime type mismatches across request payloads.

MySQL + Sequelize: Strict foreign key constraints and transactional semantics ensure tasks cannot orphan if parent projects or user accounts are modified.

5. Database Schema & Endpoints

  • Users (id, name, email, password_hash, role, created_at)
  • Projects (id, title, description, manager_id, status, created_at)
  • Tasks (id, project_id, assigned_to, title, priority, status, updated_at)
  • Key Endpoints: POST /api/auth/login, GET /api/projects, POST /api/tasks, GET /api/admin/stats (HMAC protected).

6. Security Controls & HMAC Middleware

Engineered server/src/middlewares/hmacAuth.ts: Validates incoming server-to-server requests using an HMAC-SHA256 signature generated with a pre-shared ADMIN_INTEGRATION_SECRET. Requests with missing headers or altered payloads fail immediately with 401 Unauthorized.

7. Testing & Verification

Validated endpoint responses using Postman collections; tested Socket.IO connection recovery during artificial network drops; confirmed aggregate stats queries execute in under 15ms on indexed project tables.

Architecture Deep Dive

VisionGuard AI – Enterprise Anti-Face Spoofing System

Status: Source Available • Local Demo GitHub Repository

1. Problem Statement

Conventional face recognition algorithms can be easily circumvented using printed photos (2D attacks) or high-resolution tablet replays. Security-critical verification requires real-time presentation attack detection (PAD) before granting access.

2. 3-Tier Multi-Process Architecture

[ Browser Client (React/Vite) ] |-- 1. Captures webcam video stream @ 3 FPS |-- 2. Emits Base64 frame via WebSocket | +=================> [ Python AI Microservice (Flask-SocketIO) ] |-- 3. Decodes frame via OpenCV |-- 4. Runs inference on YOLOv11 (`best.pt`) |-- 5. Emits Bounding Boxes & Confidence back |-- 6. Async HTTP POST detection stats v [ Node.js Audit Backend (Express) ] |-- 7. Persists spoof attempt audit record v [ SQLite Database (Sequelize) ]

3. Pipeline Decisions & Performance Tuning

  • Frame Rate Throttling: Throttling client capture to 3 FPS prevents buffer bloat on consumer webcams and guarantees inference times under 120ms without GPU overload.
  • Model Training: Fine-tuned Ultralytics YOLO model on balanced splits of genuine human faces and presentation attack mediums (curated Real/Fake sets).
  • Asynchronous Audit Logging: Decoupled the Node.js database logging from the live video WebSocket stream so database disk writes never stall real-time visual feedback.

4. Verification & Testing Evidence

Verified with live webcam tests against printed color photographs and mobile screen video replays. Bounding boxes correctly labeled spoof attacks in under 150ms total latency; administrative dashboard aggregated spoof events accurately.

Manufacturing Execution System (MES) – Traceability Platform

Domain: Industrial Traceability • KnowledgeQ Confidentiality Preserved

1. Problem Context & Objective

Modern industrial assembly lines require complete traceability: every component, sub-assembly, and finished unit must be tracked through designated sequential stations. If a part skips a mandatory testing or assembly step, the system must immediately reject it to prevent costly recalls and ensure safety standards.

2. High-Level Flow Architecture

[ Hardware Scanner / Station Terminal ] | v (Barcode / Serialized LOT Scan) [ Node.js / TypeScript MES API Service ] | +-- 1. Validate Station Sequence & Pre-requisite State +-- 2. Reject if prior quality inspection incomplete +-- 3. Execute transactional transition in MySQL | v [ Relational Audit Log & WIP State Tables ] | v [ Real-time Production Dashboard & Quality Metrics ]

3. My Engineering Contributions

  • API Service Endpoints: Built and maintained TypeScript service layers processing serialized part scans and station handshakes.
  • Relational Data Integrity: Designed indexed MySQL tables ensuring serialization unique constraints, parent-child component relationships, and append-only audit histories.
  • Error Handling & Edge Cases: Implemented defensive validations for barcode misreads, duplicate scans, and out-of-order station progressions with distinct error codes for line operators.
  • Agile & Release Collaboration: Participated in sprint planning, code reviews, and defect triage alongside QA and operations teams.

4. Operational Reliability & Data Consistency

Production line speed demands response times under 50 milliseconds per scan. Database queries utilize indexed foreign keys and connection pooling to avoid locking tables during concurrent high-throughput shift operations.
